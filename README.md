# fyst-to-toast

Feed per-sample telescope trajectories generated by FYST into TOAST Observations.
The adapter preserves native timestamps, scan blocks, and motion without resampling:
FYST plans the scan; TOAST uses those samples for pointing and downstream simulations.

## Status

Experimental **0.1.0.dev0**, tested with **TOAST 3.0.5** and **FYST trajectories 0.11.0**.
Trajectory input supports serial execution only. Scan-direction and Sun intervals,
MPI, and a validated real focalplane with module clocking are not yet supported.
The included focalplanes are demonstrations, not instrument models.

## Install

Use Python 3.10+ in a conda environment with TOAST and the other
[dependencies](pyproject.toml) already installed, plus setuptools 77+:

```bash
python -m pip install --no-deps --no-build-isolation -e .
```

FYST is optional for reading H5 and running SimFYST. Generation requires
`fyst-trajectories>=0.11,<0.12`; the `fyst` extra declares this dependency.
To let pip resolve the extra in your existing TOAST environment:

```bash
python -m pip install --no-build-isolation -e ".[fyst]"
```

Before any NumPy, TOAST, or FYST import, set:

```bash
export MPI_DISABLE=1 OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1
```

Restart a Python session if MPI was already initialized. The library does not
configure process-wide settings. Generation and writer CLIs disable IERS downloads
and use Astropy bundled data by default; both accept `--iers-file` for an offline table.

## Quick start

Run from the repository root with FYST installed. Choose a new output directory:

```bash
export RUN_DIR=output/quickstart
python scripts/generate_trajectory.py ces --output-dir "$RUN_DIR"
python scripts/save_trajectory_h5.py "$RUN_DIR/fyst_trajectory.ecsv"
```

Generation writes a full timeline, science-only schedule, per-sample trajectory
ECSV, and report. The writer creates `hdf5/` beside the ECSV, with one H5 per native
block and a `files.json` manifest. Existing outputs require explicit `--overwrite`.
The default scheduling window is three hours, including overhead; `daisy` and
`pong` are also available.

In Python, use the same `RUN_DIR` and the environment settings above:

```python
import os
from pathlib import Path
from astropy import units as u
from astropy.coordinates import solar_system_ephemeris
from astropy.table import QTable
from astropy.utils import iers
from toast import Data
from toast.instrument import GroundSite, Telescope
from toast.instrument_sim import fake_boresight_focalplane
from toast.mpi import Comm
from fyst_to_toast.sim_fyst import SimFYST

iers.conf.auto_download = False
run_dir = Path(os.environ["RUN_DIR"])
meta = QTable.read(run_dir / "schedule.ecsv").meta
site = GroundSite(meta["site_name"], meta["site_lat"],
                  meta["site_lon"], meta["site_alt"])
telescope = Telescope(
    "FYST-demo", site=site,
    focalplane=fake_boresight_focalplane(n_pix=1, sample_rate=10 * u.Hz),
)
data = Data(Comm(world=None))
try:
    with solar_system_ephemeris.set("builtin"):
        SimFYST(
            telescope=telescope,
            trajectory_files=[str(run_dir / "hdf5/files.json")],
        ).apply(data)
    print([(obs.name, obs.n_all_samples) for obs in data.obs])
    # Apply downstream TOAST operators here, before clearing the data.
finally:
    data.clear()
```

The caller supplies the telescope and focalplane; SimFYST validates the site and
sample rate against each input. See [downstream_maps.py](examples/downstream_maps.py)
for sky, noise, pointing, and binned maps, and [architecture](docs/architecture.md)
for the input contract.

## Conventions

**Roll.** Per-sample `boresight_roll = -nasmyth_sign * El`, with the port read from
the FYST schedule. ECSV stores degrees; H5 stores radians. Convention
`toast_q0_rz_local_z_v1` means
`Q_bore = qa.from_lonlat_angles(-az, el, 0) * Rz(roll)`, rotating about local +Z.
In FYST 0.11.0, schedule `boresight_angle` is a sky-frame angle including parallactic
rotation, so it cannot be used directly as this local roll. See the
[upstream correction proposal](https://github.com/ccatobs/fyst-trajectories/pull/2).
TOAST handles the transformation to sky coordinates.

**Clocking.** Apply each module's clocking `c` to its focalplane detector quaternion
as `Rz(-c) * Q_fp`; it is not part of boresight roll. FYST's i1–i6 identify ring
positions and run in the opposite direction to the instrument team's IM1–IM6.
Real port assignments and module clocking remain unvalidated.

**Flags and intervals.** FYST flags are enums; TOAST flags are bitmasks.
The default mapping in the tested TOAST version is:

| FYST state | Raw enum | TOAST shared flag | SimFYST interval |
|---|---:|---:|---|
| Science | 1 | 0 | `scanning` |
| Turnaround | 2 | 4 | `turnaround` |
| Unclassified / retune | 0 / 3 | 1 | `fyst_invalid` |

Raw enums are preserved. SimFYST derives intervals from contiguous sample runs
using half-open `[first, last)` spans; the turnaround mask is configurable.

**Time.** Absolute sample times are float64 Unix seconds. Generated UTC strings
are rendered to milliseconds; this display precision does not round sample arrays.
Relative times and native block boundaries are retained.

## Tests

With the environment variables above and pytest installed:

```bash
python -m pytest -p no:cacheprovider
```

Tests requiring FYST skip when it is unavailable. Optional input-dependent checks
also skip when their inputs are absent. Passing tests does not establish real
instrument calibration or agreement between independent astrometry backends.
